# Dawson Residences — requirement matrix

Classification describes the application **as it was on `main` before this branch** (evidence paths point at that code), and the "Required changes" column says what this branch did or what remains.

> The requirements PDF ("To Do List Dawson Res App.pdf") was not available when this was written. Phase 1 IDs (BILL-01…BILL-10, CARETAKER) come from the written brief. Phase 2 and 3 IDs (P2-…, P3-…) are **provisional** and should be remapped to the PDF's IDs.

Classifications: **Existing** · **Minor Modification** · **Major Modification** · **Not Supported** · **Deferred**

## Phase 1 — billing and collections (implemented on this branch)

| Requirement | Classification (before) | Evidence / file paths | Required changes (done) | Phase |
|---|---|---|---|---|
| BILL-01 Twice-monthly billing | Not Supported | `prisma/schema.prisma` `MonthlyLedger @@unique([tenantId, month])` allows one record per tenant per month; `Tenant.dueDay` single due day; `lib/due-dates.ts` | New `BillingProfile` (configurable cycle days, short-month policy, separate generate / distribute / due offsets), `Statement @@unique([tenantId, periodKey])`, draft → review → issue flow, idempotent generation. `lib/collections/calendar.ts`, `lib/collections/statements.ts`. MonthlyLedger untouched for other properties. | 1 |
| BILL-02 Recurring charges | Not Supported | Only `Unit.rentAmount Float`; ledger lines typed by hand (`app/api/ledger/route.ts`) | `RecurringCharge` per room (rent every cycle; internet monthly; parking monthly / every N months / every cycle; other), explicit rent basis (`PER_CYCLE` or `MONTHLY_SPLIT`, no default), monthly items keyed by month and carried by one configured cycle, as-needed misc charges with required description on drafts, previous balance shown automatically. Issued charges keep their amounts; settings changes affect future drafts only. `lib/collections/plan.ts`, `lib/collections/rooms.ts` | 1 |
| BILL-03 Occupant-based water | Not Supported | `MonthlyLedger.waterAmount` typed by hand | `Tenant.occupantCount` (1–4), ₱350 + ₱200 × (n−1) configurable, once monthly, room override with recorded reason, no charge when occupants unknown or room vacant | 1 |
| BILL-04 Water meter monitoring | Not Supported | — | `RoomBilling.meterId`, `MeterReading` history with date-order and decreasing-value validation, explicit meter reset/replacement, usage calc, allowance flag, `WaterExcessProposal` requiring admin approval, billed once via `excess:<id>` key. Allowance and rate **left unset** (owner decision). `lib/collections/meters.ts` | 1 |
| BILL-05 Payments and verification | Major Modification | `Payment` is one row per tenant per month (`app/api/tenant/pay/route.ts`), amount defaults to unit rent (no partial amounts), resubmission overwrites `proofUrl`, rejecting sets status back to `pending` (`app/api/payments/[id]/route.ts`), approving never updates `MonthlyLedger`, proofs saved to public bucket URLs (`lib/storage.ts`) | New `RentPayment` (PENDING / APPROVED / REJECTED / REVERSED) + `PaymentAllocation`. Partial payments, oldest-charge-first allocation, unapplied credit, atomic + idempotent approval under a per-tenant lock, reversal keeps history, rejected evidence kept, duplicate guards (request id, screenshot hash, reference no.). Settlement status derived separately from verification. `lib/collections/payments.ts`, `lib/collections/ledger.ts` | 1 |
| BILL-06 Late penalties | Not Supported | — | Enable flag, % (basis points), grace days, per-tenant exemption with reason, waivers/adjustments with reason, separate penalty lines, once per statement, never compounding. Can't be enabled until rate **and** grace are set; **off** by default. `lib/collections/penalties.ts` | 1 |
| BILL-07 Statements and balance accuracy | Major Modification | `Invoice` + PDF from `MonthlyLedger` (`lib/invoices.ts`, `lib/pdf.ts`); "previous balance" is a hand-entered `MonthlyLedger.balance` field that can be counted twice | Statements with property name + logo, tenant, room, period, due date, itemized lines, subtotal, previous balance, credits, penalties, total, payment instructions. One shared calculation (`lib/collections/statement-math.ts` + `ledger.ts`) for dashboard, portal, statements and receipts. Issued snapshot kept; later changes listed under "Since this statement was issued". | 1 |
| BILL-08 VECO receipt tracking | Not Supported | Electricity is treated as a billed charge (`MonthlyLedger.electricAmount`) | `RoomBilling.vecoAccountNumber`, `VecoReceipt` per billing month with verify/reject, missing-receipt detection, portal banner + one email reminder per month. Never touches charges, payments or income. `lib/collections/veco.ts` | 1 |
| BILL-09 Administrator dashboard | Major Modification | `app/dashboard/page.tsx`, `lib/unpaid.ts` derive status from `Payment` rows, falling back to unit rent | `/dashboard/collections`: charges issued (period), payments received (paid-on date), outstanding and overdue (as of today), pending approvals, missing VECO, water alerts, draft count; filters by month / cycle / room / tenant / payment status. Definitions printed under each figure. `lib/collections/views.ts` | 1 |
| BILL-10 Basic tenant portal | Minor Modification | Phone + PIN login (`lib/auth.ts`), `/tenant/pay`, `/tenant/documents` | `/tenant/billing`: balance, statements (current + history), partial payment upload, verification status with where each payment was applied, VECO uploads; tenant sees only their own tenancy. Old Pay page redirects for billing-enabled properties. | 1 |
| CARETAKER Minimum caretaker access | Not Supported | `User.role` "STAFF" gets full landlord access (`proxy.ts`, `lib/owner-auth.ts`) | `CARETAKER` role (`User.role`), `CaretakerProperty` assignment, `/caretaker` meter entry only; blocked from `/dashboard`, billing APIs and evidence files (enforced in `proxy.ts` and in each service). | 1 |
| SEC Protected evidence | Not Supported | Public bucket URLs (`lib/storage.ts` → `/object/public/payment-proofs/…`) | `StoredFile` in a **private** Supabase bucket (or Postgres when Supabase isn't configured), served only through `/api/files/[id]` after a per-file check; type detected from file content; 5 MB limit; `no-store` + sandbox headers. | 1 |
| AUDIT Financial history | Not Supported | — | `BillingAuditLog` for approvals, rejections, reversals, waivers, overrides, publications, settings changes; allocations and adjustments are reversed, never deleted. | 1 |
